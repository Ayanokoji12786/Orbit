- **Completed in this checkpoint:** Existing-account email OTP recovery now offers a six-digit code flow without creating a new account or exposing an unknown address. The Privacy screen requires typed DELETE and a sign-in session started within ten minutes. A service-role Edge Function records a deletion tombstone, closes hosted meetings, disconnects LiveKit participants in bounded retryable batches, removes inventoried Storage objects through the Storage API, and finally deletes the Auth user. SQL cleanup removes shared DMs and authored meeting content; write gates block new content during deletion and from lingering access tokens. The AI function now requires an active account and meeting membership, accepts a meeting UUID in place of a caller-provided title, bounds submitted history, and caps output tokens. These are **local implementations**, not deployed behavior.
- **Remaining features:** See `ORBIT_MASTER_PLAN.md` and `ORBIT_TEST_MATRIX.md`. Major gaps include general file attachments, offline/reconnect behavior, host moderation, AI transcript/summary pipeline, route-by-route accessibility, authenticated iOS/Android and two-user validation, and safe deployment.

A 202 response or service failure leaves a pending request that needs the user to retry; there is no background continuation worker. The flow expects Auth deletion to prevent refresh, but this is unverified; an already-issued JWT may work until expiry where a read path has no deletion gate. Already-issued private image URLs may remain usable for up to five minutes. Reminders on other devices are not reconciled. LiveKit, Groq, Realtime, and native behavior remain unverified.
